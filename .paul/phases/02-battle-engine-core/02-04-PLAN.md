    Tests à implémenter :

    **Player_Wins_When_Opponent_HP_Reaches_Zero** :
    - mock formula.Calculate retourne `new DamageResult(9999, false, 1.0m)` (any args)
    - mock typeChart.GetFactor retourne 1.0m
    - player.Speed=100, opponent.Speed=50 (player first)
    - opponent.CurrentHp=1

    - RunBattle → result.IsPlayerVictory == true, result.TurnsPlayed == 1

    **Opponent_Wins_When_Player_HP_Reaches_Zero** :
    - même setup mais player.CurrentHp=1, opponent.Speed=100 > player.Speed=50
    - opponentStrat doit retourner un move
    - RunBattle → result.IsPlayerVictory == false, result.TurnsPlayed == 1

    **Max_Turns_Reached_Returns_Timeout** :
    - mock formula.Calculate retourne `new DamageResult(0, false, 1.0m)` (aucun dégât)
    - les deux HP restent positifs → loop 200 tours
    - RunBattle → result.IsPlayerVictory == false, result.TurnsPlayed == 200, result.Reason == "MaxTurns"

    **Type_Immunity_Skips_Damage** :
    - mock typeChart.GetFactor retourne 0.0m pour Type1 du defender
    - mock formula.Calculate vérifié JAMAIS appelé (mock.Verify(x => x.Calculate(...), Times.Never()))
    - opponent survit malgré le loop → max turns atteint

    **Speed_Tiebreak_Is_Random** :
    - player.Speed == opponent.Speed == 50
    - mock formula retourne 9999 damage
    - lancer RunBattle 100× → les deux outcomes (IsPlayerVictory=true ET false) apparaissent au moins une fois (test probabiliste : P(tous true en 100 runs) = (0.5)^100 ≈ 0)

    Note importante sur BattleConfig : si BattleConfig n'a pas de propriété `AccuracyEnabled`, utiliser `move.Accuracy=100` dans tous les moves des tests pour éviter les misses.     Note sur DamageResult : vérifier le constructeur exact dans SDK.Core.ValueObjects.DamageResult avant d'utiliser `new DamageResult(damage, isCritical, typeMultiplier)`. Adapter si ordre différent.
